# Build 60: commit-scoped projection inputs

Android baseline: Room InvalidationTracker, EpisodesDao, ShowsDao, MoviesDao and ProgressItemsCase. Existing parameterized show_id/seq index reused. No schema migration or new empirical thresholds. EpisodeStore consumes CommitFence changes into separate derived local-input and schedule indexes. A cold read validates all catalog/journal identities and account baseline; known show changes read and replay only that show's rows, then verify cross-show journal ownership against the validated index. Conflict or invalid index triggers complete reconstruction; original malformed data fails closed. Global/uncertain changes and account switches evict indexes. Rollback preserves valid committed reads. Evidence maps are process-local, rebuilt from fully validated original account JSON; display-only detail may select by episode ID. Authority paths retain original database reads, account verification, upload and undo rules. Derived schedule position set and shared AiredSummary avoid repeated episode scans after cache hits; old disk entries reconstruct the summary once after verification. Confirmed exact disk rows are not fetched for warm memory hits; failed persistence can retry. Existing real-airtime expiry and per-show exact input signatures remain. Original full loop still assembles membership, evidence and per-show signatures; not a claim of O(1) total projection. Global writes still rebuild all validated inputs. Index memory is reclaimed on background/pressure/account reset; overlapping reads fail closed. Assumes this app's single EpisodeStore writer; no external SQLite modification supported. Host tests use real SQLite query shapes and actual production methods with a ResultSet adapter; no device latency claims.
