# v0.9.3e.2d.2 — shared reads (0.9.3.19 / build 43)

Android also exposes bulk title translation reads. HarmonyOS retains Trakt artwork sources, not TMDB/Coil parity.
- Use native Promise/RDB and typed in-flight singleflight pattern (https://pkg.go.dev/golang.org/x/sync/singleflight; https://developer.huawei.com/consumer/en/doc/HarmonyOS-Guides/data-persistence-by-rdb-store/). No new dependency or artificial concurrency/TTL. Four existing independent observation domains read concurrently with sequential pagination; failure stops new pages and drains in-flight calls before returning. Activity fences and account verification remain independent; no sync POST/DELETE, receipt or history verification coalescing. Display-only public summary/artwork and optional personal rating in-flight keys include request identity; rating keys include client/session generation/kind/activity, public summary clear increments epoch. No completed-response reuse by ReadFlight itself.
- Watched/watchlist movie list endpoints use extended=full once inside the verified account observation. Preserve exact cloud member and play counts, movie metadata flags checked against membership, valid/uncertain release date, runtime/rating and listed_at. Persist via existing account UUID-scoped observation; no token and no rating writes. Old cache accepted, once fresh observation fills missing movieDetails. Account online verification still mandatory. Calendar/progress and collection rating sort share movie data, no independent personal movie list read from Index. Current effective membership still comes from existing local+remote projection; locally added unknown movies remain conservative. Personal ratings loaded on demand only for relevant sort and keyed to current verified activity; kept in memory not persisted. Explicit release lookup remains per-session in memory. Extended payload may increase bytes vs show-only read; compare real bandwidth. Old standalone helper retained unused by Index, sync preview and writers unchanged.
- Keep title cache scan at open for local bilingual search; season cache query by exact show+season only on demand. Hydrate visible seasons before remote translation. Two resource lanes (art/detail vs translations) each sequential; lane failure doesn't suppress successful other lane. Merge field patches under per-title write serialization; incremental changed-title/season index updates; public metadata may finish after route change, private results guarded by active scope and version. No new arbitrary retry intervals; existing upstream title/season validity remains. Off-page translation for active search/sort still needed, page-based artwork rather than viewport, no background service. Native result sets and UI timings need device validation.
- Tests use production movie observation/parser with mock readAll, actual ReadFlight implementation, fixture concurrency and error drain, snapshot validation and old schema compatibility. Counts measure logical domain reads, not network packet or bytes; 393 concurrent identical callers fixture exercises shared-flight behavior, not 393 real requests. Existing batch SQL, cross-process, title sync safety tests remain mandatory. Actual device startup, networking, navigation, failure and image/translation refresh tests required; no live Trakt writes. Remaining potential risks: extended response larger, simultaneous read domains may encounter rate limiting, public cached data can be incomplete, memory for loaded seasons grows within process.
