# Discovery read model (build 47)
Baseline e08cb90b DiscoverShowsRepository, DiscoverMoviesRepository, DiscoverShowsCase, DiscoverMoviesCase, Genre and Network enums. 12h cache, 280 base, 30 anticipated, zero-based insertion at nonzero multiples of six, trending limit plus half collection size when hiding collection, recent uses same trending feed and UTC date filter. Genre and grouped network aliases forwarded to Trakt; movies ignore networks. Server effective pagination honored; no fixed extra prefetch, no new tuning constants. The existing 12-item UI page remains local. Native ArkData + existing ReadFlight, no dependencies.
Public feed cache uses client+kind+normalized request filters+limit, no account IDs, viewing/collection records or tokens. Membership is applied in memory from current validated library/hidden state. Identical public requests coalesce; cached results shown before refresh, stale retained on failure, forced refresh bypasses TTL. Old route/client results cannot publish. Store one complete public feed atomically; cache corruption is a miss, DB failure falls back to memory. Cache per query rather than upstream single active feed to prevent incorrect reuse across filters. No automatic cache pruning yet. Native pagination and offline behavior require device/network checks.
UI retains local page size, filter code entry instead of Android multi-select, no Twitter ad. Per-mode preferences persist. Async progress/collection summary published after successful row submission; mismatching request keys show updating instead of an empty-state count, prior rows may remain until commit. No authoritative watch/sync change. Public cache shared across accounts for identical client/query, private membership never persisted there. Collection size may differ temporarily before personal library is ready; subsequent explicit loads recalculate.
