# Build 55: restore parent list after detail navigation

Root cause: entering a detail replaces the parent List and releases its derived data source. The restored List initializes at index zero. Android uses RecyclerView state restoration; the HarmonyOS equivalent is a stable row ID, visible index and viewport-relative offset, scoped to account, route and filters. Capture immediately before navigation and restore after committed rows and a native layout frame. If the item no longer exists, use the nearest surviving ordinal; wait for data if the source is empty. No retained parent screen or arbitrary timer. Seven main list routes covered; the detail/history/sync review scroll containers are not part of this fix. Existing cache eviction and synchronization safety unchanged. Pure tests cannot prove native layout/offset timing; device verification required.
