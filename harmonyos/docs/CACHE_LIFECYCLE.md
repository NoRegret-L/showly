# Cache lifecycle (Build 53)
Android baseline e08cb90b: SearchViewModel.onCleared clears suggestions; progress/calendar jobs are viewModelScope-bound; translation repository is persistent and images providers are singleton. Native UIAbility.onMemoryLevel emits a deferred, coalesced notification. Route/account transitions release inactive derived caches; active page data is retained during foreground pressure; background pressure releases transient payloads. SearchRead supports an explicit resident scope and generation-gated publication; disk writes continue to captured scope but stale completions do not publish resident snapshots. Memory-only storage fallback retains backing data because it cannot be reconstructed from disk. Title startup still parses persisted rows, but publishes only title/sort/collection metadata; full payloads read by ID and released on route change. Season hydration is generation-keyed and old remote tasks cannot refill memory after eviction. A disk write already underway can complete; public compact title metadata can still publish later. Title patch writes remain serialized by ID. Search uses explicit native ON_CONFLICT_REPLACE on derived catalog table. Progress random order is stable ID hash rather than regenerated on projection, avoiding unrelated candidate invalidation; this differs from Android random comparator. Existing saved projection may carry old random values until recomputed. No new tuning, capacity or periodic cleanup. Scope of this phase is module cache ownership and event coordination, not full ViewModel migration. No authoritative snapshots, journals, account bindings, sync queues or receipts released; persisted metadata and posters are not deleted. True device memory callback delivery, RDB upsert, PSS and UI latency need device validation. Active detail is retained under foreground pressure and full title/season payloads may accumulate within a long active route; later viewport-specific pruning is separate work. No changes to network source or sync policy.
