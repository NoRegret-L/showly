# Build 56: viewport and read lifecycle

Baseline Android RecyclerView bindings and coroutine/view-model scopes (e08cb90b). Normal presentation work enumerates the native ViewportTasks set, not the backing list. Explicit business metadata dependencies are cached separately and merged; title/episode queries remain able to request non-visible metadata. Cancellation is consumer-counted; losing one consumer does not destroy a shared HTTP request until the last leaves. Discovery, summary, poster, translations, season hydration and full-catalog detail reads are covered; background evidence and sync callers without UI cancellation remain protected. TaskPool uses native Task instances and best-effort cancellation; detached consumers never run a synchronous fallback on cancel. No new thresholds, timeouts or cache size. Existing cache writes already started may finish; generation gates block stale UI. Device frame/CPU/RSS measurement and complete page ownership remain future work. Pure tests verify model semantics, not actual device throughput.
