# 三方状态同步 v0.9.3b

共同基线 B 为显式确认过且两端一致的布尔存在状态；本机 L 来自明确操作，远端 R 来自完整分页快照。账户 UUID 与域（episode/movie/watchlist）共同决定隔离边界。未知不是 false。只读快照不能推导播放历史归属。

| B | L | R | 分类 | 行为 |
|---|---|---|---|---|
| 无 | 未知 | 任意 | 未知 | 不写入 |
| 无 | 明确 | 任意 | 无基线 | 沿用原有明确操作/保护机制 |
| 有 | B | B | 未变化 | 可确认共同基线 |
| 有 | 非 B | B | 仅本机变化 | 原有同步保护 |
| 有 | B | 非 B | 仅云端变化 | 暂停反向写入；可确认采用云端状态 |
| 有 | 非 B | 非 B | 收敛 | 可推进共同基线 |

二值状态下双方均改变必然相同，不能声称可发现所有历史级冲突。重复观看、播放日期、短时间反复变化或同值重申不可由此检测。跨设备竞态仍存在。未建立共同基线的旧明确操作保留原安全流程；本机未知和仅云端仍不得创建写入。手动保存一致基线只更新符合条件的行；不覆盖未收敛基线。电影/待看和分集各自数据库事务中原子提交本机采用与新基线，不恢复旧凭证、不创建自动授权。保留所有防重/撤销约束。

验收场景：首次匹配存基线、仅本机、仅云端、共同收敛、旧未知、不同账户、远端快照变化、待确认操作阻塞采用、重新启动保留基线、采用远端后另域不变。云端操作需由用户明确授权；无需删除真实观看历史做测试。
