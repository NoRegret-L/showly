# v0.9.3e.2d — collection rules and local hidden projection
Baseline Android e08cb90b: MyShowsLoadShowsCase, MyMoviesLoadCase, MyShowsItemSorter, MyMoviesSorter, WatchlistLoadShowsCase, WatchlistLoadMoviesCase, WatchlistItemFilter, CollectionItemFilter, WatchlistItemSorter, CollectionItemSorter, HiddenLoadShowsCase, HiddenLoadMoviesCase, HiddenShowsRepository, HiddenMoviesRepository, ShowContextMenuHiddenCase, MovieContextMenuHiddenCase, SettingsSortRepository, SettingsFiltersRepository, Config, Settings.
- Main membership and status use the existing effective personal library. Collection, watchlist, hidden per media type each persist independent sort/direction, genre OR and show network OR filters (AND across categories), strict show time/movie UTC-day release rules and bilingual search. Defaults added descending; recent amount 4 from upstream Settings default. Recently added only known actual local title membership transitions after successful user writes or first eligible local episode marks; watchlist uses verified Trakt listed_at plus actual local changes. Older/imported mine entries have unknown insertion timestamps, not invented dates. Existing status classification conservative for incomplete catalogs. Android movie updatedAt/show createdAt not fully reconstructible. Missing values last; random stable in process; recent timestamp from existing progress source. Sorting is approximate when data missing. Network filter uses exact channel strings rather than upstream bundled Network enum groups; genre inputs use Trakt slugs. Collection metadata extends the existing public presentation JSON and summary cache, fetched for current page and off-page only for active metadata filters/sorts or bilingual query/title ordering, no startup-wide prefetch. Read-only personal ratings on demand under current account/session and activity, no rating writes.
- Original hide inserts archive membership, removes my/watchlist records, clears pin, may remove unwatched local catalog data, schedules hidden sync and offers separate remote progress/watchlist removal. This version deliberately uses an account/device-scoped, reversible LOCAL presentation overlay rather than removing local membership/history or changing remote intents: hide excludes from collection, progress, calendar, discovery; search/detail remain accessible with unhide, hides clear pin where persisted successfully. Unhide reveals retained underlying memberships (different from Android); no Trakt hidden read/write yet, no automatic cloud deletes, no backup extension. Existing sync writer, consent, queue, exact receipts and history deletion guards untouched. Hidden and pin preferences are separate transactions; a partial save is reported. Metadata/timestamp failures do not synthesize watch events. Local addition times saved separately from business transaction, not atomic.
- Collection List/LazyForEach uses existing IDataSource and bounded page groups: one card per text row or two per poster-grid row, same row update semantics as Build 40; recent block intentionally duplicates recent member in main list, as upstream. Native UI and device performance not verified. Existing public metadata loading is still per page rather than true viewport. Read-only hidden filter leaves sparse discovery pages; no full discovery rewrite.
- Test membership, status, hidden isolation/restore, actual date transitions, missing timestamps, strict dates and combined filters/sorts, bilingual search, cloud date validation and wiring. CI HAP compile and prior regressions mandatory. Device checks: account switches, process restart, hide from all surfaces, unhide, no remote writes, title mark/watchlist, sorting/filter settings, pagination/grid/pull refresh and performance. No claim of complete upstream hidden synchronization or full historical added-time parity.
