# Presentation scheduling (build 49)
Android baseline e08cb90b TranslationsRepository, ShowImagesProvider, MovieImagesProvider, ViewModel-scoped IO cases. Kotlin SupervisorJob failure isolation (https://kotlinlang.org/docs/exception-handling.html); ArkTS native HTTP resource lifecycle (https://developer.huawei.com/consumer/en/doc/harmonyos-guides/http-request/); HTTP 429 Retry-After RFC 6585. Existing 5-day title and 3-day season release cooldown unchanged. No dependency or new numerical tuning constant.
Four semantic lanes: local hydration, title, season, artwork/required collection metadata. Visible tasks precede background local hydration/metadata; offscreen titles use startup local index, offscreen seasons read local cache only unless an explicit detail page needs them. Unrelated title or artwork lane does not wait for slow season. Per-resource failure suppression until explicit retry/network recovery (known service deadline always retained). Pending work re-evaluates on viewport revision, scope, account, route and language; old consumer stops queued reads and cannot publish. Shared in-flight HTTP is deliberately not forcibly destroyed on consumer cancellation; it may finish into public metadata cache, native finally destroys the handle. This is logical cancellation, not socket preemption. One lane may wait for its in-flight operation before processing a new route.
Structured HTTP status for summary, title, season and poster CDN; missing vs authorization vs temporary vs limited. Trakt gate keyed by client, CDN by host, checks before native HTTP. Retry-After seconds/date, missing header conservative manual probe only; manual refresh cannot shorten known deadline. Gate is process-local and limited to presentation endpoints, not sync/other HTTP paths. Already-started requests cannot be recalled. No automatic timer or retry storm. Public cache independent of private account state; current account required for consumer publication. Poster unsuccessful temporary attempts remain retryable, known absence distinguished from failures. Same resource flights and independent local hydration retained. No change to authoritative viewing data or sync mechanisms.
Tests: actual pure policy with mocked transport, stale route cancellation, failure isolation, independent lanes, server deadline, 393 caller flight. Native network cancellation and full device behavior are not demonstrated by host tests. TMDB/AWS not added; existing HTTPS validation retained.

Follow-up: failed resources retain their captured failure state even if the viewport changed while awaiting I/O; explicit retry advances the failure epoch. Missing summaries are remembered until explicit refresh. Cached poster is committed/published before remote metadata, and the page is rechecked before starting that remote operation. Additional test covers scroll during rejection.
