# Build 59 artwork pipeline

Android baseline e08cb90b: ShowImagesProvider, MovieImagesProvider, EpisodeImagesProvider, TmdbImage Wilson score, GlideExtensions and view clearing. OpenHarmony native async CoreFileKit and ImageKit, ArkUI Image sourceSize (documented in vp, native density conversion), autoResize and syncLoad(false). No new dependency or empirical tunables. Existing ConsumerReadFlight shares downloads by normalized source/type/media/full URL identity. SHA-256 filenames separate URL paths and source identity. Existing legacy files are validated and reused only as a compatibility fallback when no candidate basename collision is known; they are not promoted into verified new identities. Image metadata checked before publication; actual native decoder failures quarantine the URI, clear only matching published state, allow recovery then stop repeating the same failing URI. Cache writes retain temp validation and atomic rename; cancellation before replacement aborts; no durable business writes changed. Native component owns decode lifecycle; no separate app-resident PixelMap pool or proof of native decoded-bitmap sharing. Source selection and custom precedence are tested pure rules matching the original; authorized TMDB/AWS remote integration and persistent custom image selection are NOT enabled in this build, because credentials/authorized endpoint and UI contracts were not supplied. Trakt remains the only active remote source. Episode still fallback is a selection rule only, not a new episode image UI. All show-progress sorts request Chinese title dependencies because upstream comparators use titles as tie breakers. Test adapter validates production cache validation branches, not real native decoder output. Device memory, scrolling, real sourceSize behavior and decode performance require device validation.
