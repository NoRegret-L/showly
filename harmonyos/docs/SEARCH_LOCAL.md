# Local-first search (Build 50)
Baseline e08cb90b SearchViewModel, SearchQueryCase, SearchSuggestionsCase, SearchRecentsCase, SearchFiltersCase, SearchSortingCase; two-character suggestions, five per type then votes descending, five recents, remote limit 50, rank/name/year ascending/descending. ArkData SQLite native batch writes and current TaskPool/ReadFlight; no new numerical tuning. Formal search retains remote rank including semantic matches, appends literal local matches, filters and sorts locally. Local results/suggestions remain when offline. Search options reset on submission per original; localized title sorting uses uppercase lexicographic comparison. Existing normalization also handles diacritics. Suggestions are from observed local catalog, not a full Trakt dump. Discovery feed and successful explicit remote search seed scoped catalog; private personal library is an ephemeral input. Title translations are joined from existing presentation index, no duplicate translation database. Public index strips watched flag. History and catalog scoped by client and verified account/device; unverified account has no private index/history. History saves successful remote queries and preserves upstream duplicate behavior, capped to five. Scope/route/query generation gates stale results; logical cancellation (shared HTTP may finish), latest local worker request coalesces pending input; no auto remote keystroke calls. Search HTTP uses existing presentation service gate. Cache loaded once per scope; TaskPool receives compact candidates, not episode data, but still serializes the catalog snapshot per local query. Disk open fallback is memory, disk write failure does not erase visible results. No authoritative viewing or synchronization writes. Device latency, real weak network, memory growth and native cancellation not proven by host tests. Old discovery cache is seeded on a subsequent successful feed publication, not migrated eagerly.

Follow-up: stable ID order across warm and cold local catalog; original DAO has no explicit order. Immutable catalog snapshots only change on actual persisted metadata changes. Main-thread merged candidate list reused across query and sort changes until catalog, library, language or title revision changes. TaskPool still serializes that snapshot. Added real out-of-order async response fixture. Search success/failure updates searching state before local publication.
