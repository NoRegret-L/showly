## 核心缺口与实施顺序

1. **v0.9.2a（P0）**：电影与待看状态拆分、设计可回滚的迁移、只读差异预览。参考 Android TraktSyncService 和 TraktSyncWorker；使用独立账户绑定、明确事件、稳定 ID、完整分页。先验证旧收藏无损，绝不把布尔 watched 推断成云端删除。
2. **v0.9.2b（P0）**：手动确认电影及待看增量写入，复用已验证的分集保护机制但隔离实体类型；只有验证过的电影单次历史 ID 才可删除，待看移除不得影响观看历史。补齐云端快照与离线恢复。
3. **v0.9.3（P0/P1）**：用户可控备份、迁移回归、三方冲突检测；随后独立追剧进度、电影进度、日历与观看历史。没有可靠基线时保持冲突，不默认覆盖。
4. **v0.9.4 及后续（P1/P2）**：列表、隐藏、评分、过滤、本地化、详情扩展、统计；再评估通知/卡片和可选 TMDB。遵守 BYOK，功能需按 API 可用性决定。
5. **v1.0.0-rc → v1.0.0**：先完成 P0 及核心 P1，逐项记录 P2 未实现项并公开说明，用户确认个人稳定版范围。不得以版本号宣称 Android 全功能等价。生产签名、发布授权另行处理。

## 风险、收益及影响范围

| 方案 | 收益 | 风险 | 影响范围 |
|---|---|---|---|
| 使用原版服务与模型语义作为参考，不逐行搬运 Android 框架 | 减少行为差异 | 平台/API 差异需验证 | 局部模块 |
| 原生 RDB + additive schema + 显式日志 | 原子写入、可恢复 | 迁移丢失、账户串号 | 全局本地数据/同步 |
| 保留上传凭证及完整回读 | 降低重复和误删 | 多设备竞争与未知结果仍需核对 | 云端同步 |
| Hypium/arkXtest + 纯逻辑 fixture | 可重复验证 | 设备测试环境未建立 | 测试基础设施 |
| 分阶段发布 | 可回归并保留旧产物 | 多个版本维护成本 | 发布流程 |

**去经验化约束**：事件序号定义本机先后，稳定 ID 定义实体，活动版本定义云端快照；没有可靠三方基线时不以任意时间阈值或权重裁决冲突。API 页大小、队列批次应取自服务端规范、响应和实测，不凭空引入同步阈值。
