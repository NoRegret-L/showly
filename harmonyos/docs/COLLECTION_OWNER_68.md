# Build 68 — collection ownership, first stage

Android MyShowsViewModel and MyMoviesViewModel have separate item state and loading jobs. Native collection now uses separate physical list owners, revision memos, recent memos, incremental order and sort-job slots by media kind. Known show/movie commit IDs invalidate only the corresponding collection owner; unknown commits retain full invalidation. Inactive derived collection rows and order are released; account resets clear both. Existing shared authoritative stores, filter persistence, scroll scope and sync fences are unchanged. Index still coordinates selection, filter controls, loading/error and several repository reads; field-level dependencies and full controller extraction are not complete. No new runtime dependency, threshold or authority schema. Host regression adds 100 opposite-kind commit isolation checks per 393/10k fixture. Device behavior and HAP compilation require CI/device verification.
